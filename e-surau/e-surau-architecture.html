System Architecture Briefing

e-Surau — Surau Management Platform

Full-stack, serverless, edge-deployed web application for community (kariah) administration: membership, death-benefit scheme (khairat), finances, facility rental, vendors, and programmes. This document maps the stack & backend for developer review.

🏛️ Surau Ar Raudhah, Eco Majestic ~540 members Single-tenant · production Prepared for developer handover

Stack at a glance

Modern TypeScript stack — one language end-to-end, serverless runtime, managed Postgres.

Language

TypeScript everywhere (frontend + server). No separate backend language.

Framework

Next.js 14 (App Router) with React 18 Server Components.

Runtime

Cloudflare Workers (edge, serverless) via OpenNext adapter.

Data

Supabase — PostgreSQL, Auth, Storage, Row-Level Security.

How a request flows (backend mapping)

There is no separate REST API tier. The browser talks to server-rendered pages & Server Actions; those talk directly to Postgres through Supabase. Payments go out to CHIP and come back via webhook.

Security & access-control model

Defence in depth — enforced at the database, not just the UI.

🔐 Row-Level Security (RLS)

Postgres RLS policies gate every table. A member can only read their own records; staff access is granted by role — enforced in the DB even if the app layer is bypassed.

👥 Role-based access (RBAC)

Postgres enum peranan_jenis: admin, bendahari (treasurer), ajk (committee), imam, kerani (view-only clerk), ahli (member) + a master super-admin flag.

🛡️ Security-definer RPC

Sensitive writes (registration, linking, claims) run through vetted PostgreSQL functions with fixed search_path — not raw table writes from the client.

🔑 Secrets management

Payment keys stored as Cloudflare Secrets (encrypted), never plaintext vars. Service-role key used only in server actions, never shipped to the browser.

🗂️ Private storage

IC images & selfies live in a private bucket (salinan-kp); only sponsor logos are public. Signed access server-side.

⚖️ PDPA-aligned

Consent capture, e-signature, biometric selfie treated as sensitive data, retention & disclosure policy pages, data shared only with JAIS.

Runtime configuration (no-redeploy switches)

Operational flags live in a DB table (tetapan_sistem), toggled by the super-admin — no code deploy needed.

Functional modules

👤 Membership

Gated registration by IC, guided IC camera + watermark, e-signature, kemas kini → SU → chairman → approve workflow.

Opt-in scheme, multi-year packages (1/3/5/10 yr), dependants coverage, compensation payout tracking.

Collections, expenses, categories, payment vouchers (baucer), fund/tabung summaries, receipts.

🏛️ Rental (sewaan)

Space/equipment booking, calendar, cost calc, deposit, online or cash payment, refund policy.

🤝 Vendors / Suppliers

Gated self-registration (individual vs company), claims → verify → voucher → pay → slip match.

🕌 Programmes & Tahlil

Events with RSVP & closed invitations, weekly Yaasin & Tahlil deceased-name submissions.

Build & deploy pipeline

  • Source → GitHub (single repo, main branch)
  • CI/CD → Cloudflare auto-builds on push: opennextjs-cloudflare build → deploy to Workers
  • Database → migrations run manually in Supabase SQL Editor (phased, idempotent)
  • Config → env as Cloudflare Secrets (persist across deploys); public vars via NEXT_PUBLIC_*
  • Observability → Cloudflare Workers observability enabled
